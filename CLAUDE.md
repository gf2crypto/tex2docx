# CLAUDE.md — правила для Claude в репозитории tex2docx

Ты пишешь этот проект вместе с Иваном (автор, математик, пользователь LaTeX).
Прочитай этот файл целиком перед первой правкой в сессии, затем
`ROADMAP.md` (что делаем сейчас) и `docs/architecture.md` (как устроено).

## Что за проект

CLI-конвертер LaTeX → .docx для математических статей:
нативные формулы Word (OMML), теоремы как стили Word, нумерация ровно как в LaTeX.
Работает локально, без агента: `tex2docx main.tex`.

## Главный принцип: спрашивай TeX, а не угадывай

Все, что требует семантики TeX (номера, макросы, вид рисунков), получаем
**запуском настоящего LaTeX**: номера из `.aux`, рисунки через пакет `preview`.
`texscan.py` — это сканер скобок, а не парсер TeX, и он не должен им становиться.
Если хочется написать эвристику, которая угадывает результат TeX, сначала
подумай, нельзя ли спросить сам TeX. Если нельзя — обсуди с Иваном.

## Инварианты (не нарушать)

1. **Исходник пользователя не меняется.** Все промежуточные файлы — только в `ctx.workdir`.
2. **Ничего не теряется молча.** Все, что сделано неточно или пропущено, попадает в отчет
   (`ctx.report` в Python, `t2d.report(...)` в Lua). Код отчета стабилен: `этап.что-случилось`.
3. **В отчете нет текста документа.** Только имена команд/окружений/меток, числа, номера строк.
   Отчет Иван отправляет в чат вместо статьи — это канал без утечки содержимого.
   На это есть тест (`test_collect_pandoc_messages`).
4. **Лучше честная деградация, чем неправильный результат.** Например, если число рисунков
   не совпало с числом страниц `preview`, рисунки не подставляются вовсе.
5. **Два представления исходника:** `ctx.latex_tex` (компилирует LaTeX) и `ctx.tex` (читает pandoc).
   Этап, меняющий структуру (вставка меток), меняет оба одинаково. **Число строк не меняется**
   ни в одном из них: по номеру строки отчет находит исходный файл (`ctx.line_map`).
6. **Реальных статей в репозитории нет.** Корпус `tests/corpus/` — только синтетика.
   Папка `private/` в `.gitignore` для локальных прогонов Ивана; ее не читать без просьбы
   (запрет на чтение закреплен в `.claude/settings.json`, образец — `docs/claude-settings.example.json`).

## Как устроен код (кратко)

- `src/tex2docx/pipeline.py` — список этапов `STAGES` по порядку; у каждого флаг `fatal`.
- `src/tex2docx/stages/*.py` — этапы; у каждого `run(ctx)` и в докстринге
  `Status: implemented | PARTIAL | NOT IMPLEMENTED (Mx)` + спецификация TODO.
- `src/tex2docx/filters/*.lua` — Lua-фильтры pandoc; данные получают из JSON
  (`t2d.load(doc.meta)`), о проблемах сообщают строкой `[t2d] <level> <code> <detail>` в stderr.
- `tools.py` — единственное место, где запускаются внешние процессы.
- `data/reference.docx` — шаблон стилей; собирается `scripts/make_reference_docx.py`,
  результат коммитится. Стили, которые назначают фильтры (`custom-style`), должны в нем быть.

Подробно: `docs/architecture.md`. Поведение pandoc, на которое мы опираемся
(и которое обходим): `docs/pandoc-behavior.md` — дополняй его при каждой новой находке.

## Команды

```sh
pip install -e '.[dev]'                 # установка в режиме разработки
pytest -q                               # все тесты (сквозные пропускаются без pandoc/latexmk)
pytest -q -m "not e2e"                  # только быстрые
pytest -q -rxX                          # показать xfail/xpass — это дорожная карта
ruff check src tests scripts            # линтер
tex2docx tests/corpus/basic/main.tex -o /tmp/out.docx --workdir /tmp/wd   # ручной прогон
python scripts/make_reference_docx.py   # пересобрать шаблон стилей
```

Посмотреть результат глазами: `soffice --headless --convert-to pdf out.docx`.
LibreOffice рисует OMML приблизительно (теряет полужирный в формулах, показывает «¿» на
месте `&` в выравнивании). Окончательная проверка вида — в Word у Ивана.

## Как работаем

- **Тест сначала.** Новая возможность или исправление начинается с кейса в корпусе
  (`tests/corpus/<case>/main.tex` + `expect.yaml`) или юнит-теста. Запланированное, но
  не сделанное — в `xfail_*` в `expect.yaml`; когда тест стал XPASS, перенеси пункт в строгий список.
- **Один шаг дорожной карты — одна сессия/ветка.** Закончил — обнови `ROADMAP.md`
  и строку `Status:` в докстринге этапа.
- **Архитектурные решения** (новый этап, смена подхода, новая зависимость) — сначала
  предложи Ивану, после согласия запиши ADR в `docs/decisions/NNNN-*.md`.
- **Неочевидный выбор — спроси**, а не решай молча. Очевидное — делай.
- **Отчет от Ивана** (`*.report.md` с его статьи) разбирай командой `/triage-report`:
  каждая строка отчета превращается либо в кейс корпуса + исправление, либо в осознанное
  «не поддерживаем» в `docs/limitations.md`.
- Коммиты маленькие, сообщение по-английски в повелительном наклонении
  (`Add equation numbering filter`). Без `git push` и без переписывания истории, если не просили.

## Стиль кода

- Python ≥ 3.10, аннотации типов, `from __future__ import annotations`, ruff (конфиг в `pyproject.toml`).
- Идентификаторы, докстринги и комментарии в коде — по-английски; документация в `docs/` и
  сообщения отчета для человека — по-русски.
- Регулярные выражения по TeX: всегда `(?<!\\)` там, где важно не поймать экранированное.
- Lua: каждый фильтр начинается с подключения `t2d`, работает через `function Pandoc(doc)`,
  ничего не печатает в stdout.
- Новые внешние зависимости только по согласованию. Сейчас: pandoc ≥ 3.1, TeX Live с latexmk,
  poppler (`pdftoppm`); Python: python-docx, lxml, PyYAML.

## Общение с Иваном

- По-русски. Никогда не используй букву U+0451 (е с двумя точками) — ни в ответах, ни в файлах.
- Пиши «т.е.», а не «то есть»; без слов-паразитов.
- Формулы в чате — `$...$`.
- Окружение Ивана: macOS (Intel), Homebrew в `/usr/local`, TeX Live/MacTeX, Emacs.
  Пути и команды в инструкциях для него — под macOS.

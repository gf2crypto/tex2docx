# Корпус docx2tex

Каждая папка — один кейс: `make.py` (строит `input.docx` средствами python-docx, чтобы в
репозитории не лежали бинарники и чтобы было видно, из чего документ состоит) и `expect.yaml`.
`tests/docx2tex/test_corpus.py` собирает docx, конвертирует и проверяет.

**Только синтетика.** Реальных глав соавторов здесь нет. Проблема из отчета по реальному
docx воспроизводится минимальным выдуманным документом.

Два рода кейсов:

- **Word-набранные** (`word-*`): документ, какой принес бы соавтор: стили Word по умолчанию
  (Заголовок 1, Обычный), прямое форматирование, формулы OMML (их XML берется из
  `fixtures/omml/*.xml` — это вывод pandoc для коротких формул), таблицы, списки, картинки.
- **От tex2docx** (`t2d-*`): docx получен из кейса корпуса tex2docx; проверяется контракт круга
  (`docs/docx2tex/roundtrip-contract.md`). Такие кейсы не хранят docx: `make.py` вызывает
  `tex2docx` над `tests/corpus/<case>/main.tex`.

Формат `expect.yaml`:

- `tex_contains` / `tex_not_contains` — строки в полученном `.tex`;
- `compiles` — `--standalone`-вариант собирается `latexmk` без ошибок;
- `aux_labels` — метка → номер в `.aux` после сборки (номера как у исходника);
- `packages` — пакеты, которые отчет требует подключить;
- `report_absent` — коды, которых в отчете быть не должно;
- `xfail_*` — запланированное, пока не сделано.

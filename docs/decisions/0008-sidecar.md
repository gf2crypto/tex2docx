# ADR 0008. Документ-спутник `<имя>.t2d.xml`

Статус: принято (2026-10-31).

## Контекст

При переводах туда-сюда часть сведений нет ни в docx, ни в LaTeX-фрагменте: какие метки
стояли за номерами, как объявлены теоремы, какой язык и профиль оформления, какие макросы
автора подменялись. Заказчик предложил общий файл настроек перевода, который едет вместе
с документом и который можно править руками.

## Решение

Рядом с результатом каждого инструмента пишется `<имя>.t2d.xml` (`tex2docx/sidecar.py`):
источник, язык, профиль, имена подписей, объявления `\newtheorem`, соответствие
«закладка → метка», ключи цитат «номер → ключ `\cite`» (M1), макросы. Простой XML без текста документа. docx2tex читает спутник
рядом с docx (`chapter.t2d.xml`), использует его данные и пишет обновленный рядом с `.tex`;
tex2docx в следующем круге — наоборот. Приоритет настроек: ключи командной строки →
спутник → конфиг → умолчания. Если спутника нет, инструменты работают по эвристикам
(документ, набранный в Word).

## Альтернативы

- Только копия внутри docx: переживает переименование, но невидима и неправима без инструментов;
  у `.tex` аналога нет. Сделана дополнением: tex2docx кладет тот же XML в custom XML part
  `customXml/itemN.xml` (`sidecar.embed`), docx2tex читает его, если файла рядом нет. Не
  `docProps/custom.xml`: строковое свойство документа Word обрезает до 255 знаков при сохранении,
  а custom XML parts Word и LibreOffice сохраняют как есть (проверено на LibreOffice).
- JSON: равноценно; XML выбран по просьбе заказчика и потому что его читают Word-люди.

## Последствия

- Спутник — часть контракта круга: поля добавляются, но не переименовываются.
- `.t2d.xml` не коммитится (в `.gitignore`), как и отчеты.

# ADR 0007. Обратный инструмент docx2tex — в том же репозитории, на pandoc

Статус: предложено (2026-10-31), ждет согласия.

## Контекст

Отчет пишется в LaTeX, соавторы приносят главы в Word. Нужно получать `\input`-фрагмент LaTeX
из docx офлайн, стандартным LaTeX, и чтобы многократный прогон документа через оба инструмента
не разваливал его.

## Решение

1. **Тот же репозиторий, второй пакет** `src/docx2tex/`: общие `report.py`, `tools.py`,
   `config.py`, таблицы имен и стилей, общий корпус для тестов круга. Отдельный репозиторий
   развел бы контракт круга по двум местам.
2. **Ядро — pandoc** (`-f docx+styles`): структура, стили как `Div`, формулы OMML → LaTeX
   через texmath. Свое — чтение того, что pandoc выбрасывает (закладки, поля, свойства
   документа), Lua-фильтры структур и нормализация текста.
3. **Выход — фрагмент**, по умолчанию без преамбулы; нужные пакеты и `\newtheorem` —
   в отчете; `--standalone` для самопроверки сборкой.
4. **Контракт круга** — отдельный документ и тест; tex2docx получает в M4 запись метаданных
   круга в `docProps/custom.xml` (метки, объявления теорем) — единственное изменение
   tex2docx ради обратного инструмента.

## Альтернативы

- LibreOffice `--convert-to tex` / writer2latex: офлайн, но формулы — через формат LibreOffice,
  стили Word не различает, качество низкое. Отвергнуто.
- Свой разбор OOXML целиком: полный контроль, но формулы (OMML) пришлось бы переводить самим —
  это и есть texmath. Отвергнуто; свой разбор — только для закладок и полей.
- Метаданные круга в скрытом тексте документа: ломается при правке в Word. Свойства документа
  правкам не мешают и переживают сохранение.

## Последствия

- Качество формул ограничено texmath (OMML → LaTeX): проверяется на корпусе, расхождения —
  в `docs/pandoc-behavior.md` (раздел «docx reader»).
- tex2docx и docx2tex выпускаются вместе: версия контракта — в обоих.

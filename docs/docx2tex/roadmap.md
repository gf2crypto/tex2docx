# docx2tex — дорожная карта

Обратный инструмент: часть отчета, написанная в Word, становится фрагментом LaTeX и
встраивается в существующий документ одной командой `\input{}`. Исполняемая часть дорожной
карты — `xfail_*` в `tests/docx2tex/corpus/*/expect.yaml` и в `tests/roundtrip/`.

## Требования (от заказчика, 2026-10-31)

1. **Офлайн.** Ни один этап не обращается к сети. Инструменты те же, что у tex2docx:
   pandoc, TeX Live, poppler, Python; ничего нового ставить не нужно.
2. **Минимум нового в LaTeX.** На выходе — обычный LaTeX: `article`/`amsmath`/`amsthm`/
   `graphicx`/`booktabs`, окружения `theorem`/`equation`/`align`/`figure`/`table`/
   `itemize`/`enumerate`. Никаких своих пакетов и макросов; все, что нужно подключить,
   перечислено в отчете и в `\input`-фрагменте не дублируется, если уже есть в основном документе.
3. **Устойчивость круга.** `tex → docx → tex → docx → …` над одним документом не накапливает
   мусора: номера и ссылки не меняются, текст не обрастает пробелами, пустыми абзацами
   и лишними `{}`; результат второго круга совпадает с первым (это тест, см. ниже).

Основной сценарий: отчет пишется в LaTeX, соавтор приносит свою главу в Word (набирал сам
или правил docx, полученный от tex2docx). Нужно с минимальными усилиями получить
`chapter.tex`, который `\input` в отчет, и чтобы он собрался с первого раза.

## M0 — каркас

- [ ] Пакет `src/docx2tex/`, CLI `docx2tex chapter.docx [-o chapter.tex] [--standalone]`,
      тот же конвейер этапов над `Context`, тот же отчет без текста документа
      (`chapter.report.md`), общие с tex2docx `report.py` и правила `CLAUDE.md`.
- [ ] Этап `extract`: распаковка docx, `word/document.xml`, стили, картинки, закладки и поля
      (pandoc их теряет — читаем сами, см. `architecture.md`).
- [ ] Этап `pandoc`: `pandoc -f docx+styles -t latex` с фильтрами; формулы OMML → LaTeX
      средствами texmath.
- [ ] Этап `normalize`: типографика Word → TeX: `—` → `---`, `«»` остаются (UTF-8), неразрывный
      пробел → `~`, `…` → `\dots`, двойные пробелы, пустые абзацы, ручные переносы строк.
- [ ] Этап `emit`: фрагмент (по умолчанию) или полный документ (`--standalone`: преамбула
      с `inputenc`/`fontenc`/`babel` и нужными пакетами); компиляция `--standalone`-варианта
      как самопроверка (`latexmk`), ошибки — в отчет.
- [ ] Корпус `tests/docx2tex/corpus/` (синтетические docx, см. README) и сквозной тест:
      фрагмент вставляется в эталонный `main.tex` и собирается.

## M1 — структуры tex2docx узнаются обратно

Что tex2docx кладет в docx, docx2tex обязан прочитать без потерь (это «контракт круга»,
`docs/docx2tex/roundtrip-contract.md`):

- [ ] стили `Theorem`/`Definition`/`Remark`/`Proof` → окружения amsthm; имя окружения —
      по слову заголовка («Теорема» → `theorem`, «Лемма» → `lemma`, …; таблица в конфиге);
      номер из заголовка отбрасывается (его даст LaTeX), необязательный аргумент из скобок;
- [ ] абзац стиля `Equation` (`<tab> формула <tab> (номер)`) → `\begin{equation}`/`align`
      (несколько строк подряд с `&` → `align`), без номера → `\[ \]`; `\label` — из закладки
      `t2d_<метка>` (живые номера) или из текста номера (`eq:N` при отсутствии метки);
- [ ] ссылки: поля `REF t2d_<метка>` и гиперссылки на закладки → `\ref`/`\eqref`;
      текстовые «(2.1)» без поля — остаются текстом, в отчете `refs.plain-number`;
- [ ] заголовки `Heading 1..3` → `\section`/`\subsection`/`\subsubsection`; номер «1 Введение»
      в тексте заголовка отбрасывается;
- [ ] `Image Caption` / `Table Caption` с «Рис. N.» / «Таблица N.» → `figure`/`table`
      с `\caption`, картинка в `images/<имя>.png`;
- [ ] `Algorithm Caption` + абзацы `Algorithm` → `algorithm`/`algorithmic` (обратное
      `stages/algorithms.py`: `function`/`if`/`end if`/номера строк);
- [ ] библиография: абзацы `Bibliography` → `thebibliography`, цитаты «[1, 2]» → `\cite`
      по номеру (ключи `bib:N`); если рядом есть `.bib`/`.bbl` исходного документа —
      сопоставление по тексту записи (M3).

## M2 — документ, набранный в Word руками

- [ ] Прямое форматирование вместо стилей: полужирный/курсив → `\textbf`/`\emph`;
      абзац, начинающийся с «Теорема 3.» полужирным, → `theorem` (эвристика, в отчете);
      центрированный абзац из одной формулы → выносная формула.
- [ ] Формулы Word в «линейном» виде, формулы-картинки, формулы MathType (OLE) → отчет
      `math.not-omml`, картинка переносится как есть.
- [ ] Таблицы: объединенные ячейки → `\multicolumn`/`\multirow`, рамки → `booktabs`
      или `|`, ширина — `p{}` по ширине столбца.
- [ ] Списки Word (нумерация через `numbering.xml`) → `enumerate`/`itemize` с вложенностью.
- [ ] Сноски, перекрестные ссылки Word (`REF _Ref…`, подписи `SEQ Рисунок`) → `\label`/`\ref`.
- [ ] Картинки EMF/WMF → PDF через LibreOffice, если есть; иначе отчет.
- [ ] Макросы основного документа: конфиг `macros:` в обратную сторону
      (`\mathbf{G}` → `\matr{G}` там, где это буквенная замена) — чтобы фрагмент выглядел
      как написанный автором.

## M3 — круг и интеграция

- [ ] Тест круга: для каждого кейса корпуса tex2docx `tex → docx → tex → docx`, второй docx
      совпадает с первым по зонду (текст, число формул, стили, поля) и `tex → docx → tex`
      дает фрагмент, который компилируется и дает те же номера в `.aux`.
- [ ] Стабильность текста: после второго круга `normalize` ничего не меняет (idempotent).
- [ ] `--into main.tex`: фрагмент пишется рядом с основным документом, в отчет — какие
      пакеты и `\newtheorem` в его преамбуле отсутствуют (сравнение с `collect_decls`).
- [ ] Библиография по тексту записей: сопоставление абзацев `Bibliography` с `.bib`
      основного документа → `\cite{key}` с настоящими ключами.
- [ ] Windows: та же переносимая папка, `docx2tex.bat`.

## Сознательно не делаем

- Восстановление исходного `.tex` символ в символ после Word: цель — корректный и
  аккуратный LaTeX, а не прежний текст.
- Оформление (шрифты, размеры, цвета, отступы) из docx не переносится: его задает
  преамбула основного документа.
- Формулы, которых нет в OMML (картинки, MathType), не распознаются.
